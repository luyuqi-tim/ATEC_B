# 参考项目：BinWalker，以及本任务的篮子设计

日期：2026-10-21。范围：资料研究、源码阅读和概念设计。没有安装外部工程、下载权重、执行数值求解、修改机器人资产或运行训练与仿真。

2026-10-23 补充：在“一周开发、优先直接复用”的约束下，应以 [BinWalker 一周复用审计](BinWalker_一周复用审计.md) 的结论为准。本篇推荐的是学习和模块适配样板，不代表已有可直接部署的 B2 抓取方案或数据集。

## 1. 导师式结论

当前最适合重点模仿的项目是 **BinWalker**：四足机器人＋Z1 机械臂＋随车垃圾箱，任务是发现、抓取、暂存垃圾，并在卸载位置清空容器。

建议借鉴它的“几何感知＋逆运动学＋预设动作＋状态机”方法，同时保留老师提供的 B2 行走模型，并补上本作业要求的自主搜索、导航和得分确认。它是可研究的工程样板，尚未证明能直接运行在本教学包中。

- 几何感知：从图像和深度计算物体的位置、长轴方向等空间信息。
- 逆运动学 IK：先指定夹爪要去的位置和朝向，再反算各关节的角度。
- 预设动作 primitive：准备好可以重复执行的小动作，例如“移到篮子上方”。
- 状态机 FSM：记录当前处在哪一步，根据结果决定下一步、重试或退回。
- 复用：可以取用代码或模块，但需要核对接口、依赖、许可及效果。
- 模仿：借鉴处理问题的步骤，在我们自己的机器人和接口上实现。

## 3. BinWalker 做了什么

论文：[BinWalker: Development and Field Evaluation of a Quadruped Manipulator Platform for Sustainable Litter Collection](https://arxiv.org/html/2603.10529v1)。

它使用 Aliengo 四足机器人、Z1 机械臂和随车容器。论文展示塑料瓶收集及机械臂操作容器卸料；抓取模块根据视觉提供的目标进行运动学求解，装载和卸料等重复过程采用预设动作。

需要保留的事实边界：论文实验中的接近物体和前往卸载区域由人用手柄控制，自主导航明确在研究范围之外。它不能直接替代本作业的全自主搜索与回桶导航。

论文视觉部分可以这样理解：

1. 实例分割：把图像中属于“这一个瓶子”的像素单独圈出来，比只画矩形框更细。
2. PCA 主成分分析：对瓶子的轮廓找出“最长的方向”，辅助确定夹爪怎样转。
3. 深度反投影：用深度和相机内参，把二维像素换成相机前方的三维位置。
4. 时序平滑：综合连续几帧的结果，减少位置和方向抖动。

这些是方法参考。当前核查的代码树中没有找到对应的完整 YOLO 检测发布节点；部署控制器订阅外部 `detections3d/grasp_poses` 结果。因此不能宣称仅运行当前仓库就已经包含论文的全部视觉链路。

### 与三种作业物体的关系

- 芥末瓶：可以研究类似“位置＋长轴＋可夹部位”的几何方法；仍需验证瓶盖、瓶身和躺倒姿态的区别。
- 糖盒：可以研究盒子方向和相对较窄的夹取边；图像中心未必是夹爪能夹住的位置。
- 香蕉：弯曲形状会使“整根最长方向”不等于合适夹取方向，可能需要选择局部段或多种候选。

以上是针对本任务的设计推断，尚未进行视觉和抓取实验。

源码审查发现的适配点：

1. **身体调节接口不同。** BinWalker 的 IK 可以同时优化机身高度、俯仰和臂关节。我们的底层只接收前后速度与转向速度。不能直接照搬“弯腰够物体”；初版应限制为现有身体姿态下的机械臂可达目标，并通过移动站位辅助接近。
2. **关节零位不同。** 其状态机包含首关节 1.57 弧度的实验零位偏移；夹爪闭合目标为 0.1。我们的夹爪上限为 0，其他关节也要按自己的 URDF 重新核对。
3. **执行节奏不同。** 其动作函数用 `time.time()` 和 `time.sleep()` 分段推进。在本包中，运行器每次调用 `predicts` 后才推进仿真，不能把整段等待循环搬进去；应按每个仿真控制步更新一点动作。
4. **坐标来源不同。** 其坐标转换函数读取 MuJoCo 模型中的身体与相机位置。本作业应使用已知的挂载关系和可用关节状态建立相对变换，不把仿真内部真实位姿当作额外观测。
5. **求解成功不等于抓取成功。** 其 IK 返回成功主要检查位置误差，朝向误差虽计算但未合入成功条件；声明的碰撞避让约束也没有加入该文件当前启用的 limits 列表。我们要自行定义位置、朝向、轨迹和夹持验证条件。
6. **外观模型不等于实体容器。** 该版本 XML 中 `trash_box` 使用 `visual` 类，类定义的碰撞参数为零。这个仿真模型里的箱子显示项，不能直接当成本作业可承接物体的实体篮子。论文实物箱的机械功能与此显示模型要分开理解。

主仓库 [LICENSE](https://github.com/iit-DLSLab/trash-collection-isaaclab/blob/76c51c4c08e5762d00c75f36cb07aa3e525d6990/LICENSE) 为 BSD-3-Clause。后续如实际复制代码，需要保留相关声明，并分别检查依赖和资产的许可。当前没有复制其代码或资产进工程。

## 5. 我们可以模仿的方法

第一版候选流程：

`搜索目标 → 估计相对位置和可夹方向 → 走到可达位置 → 停稳 → 移到预抓取点 → 靠近 → 闭爪 → 小幅抬升并验证 → 投放或放入随车篮子 → 验证 → 继续`

需要动态计算的部分：物体每次出现的位置、抓取方向、接近站位。

可以准备重复动作的部分：打开夹爪、移到已知的篮口上方、收臂、到固定投放位置附近后的释放轨迹。预设动作也必须随当前状态检查，并不等于一次写死后永不变化。

这套方法的主要优点是能够逐步解释和检查：发现错误时，可以分清是视觉定位不准、目标够不到、动作路径不合适，还是夹爪没有拿住。

## 6. README 是否要求必须安装篮子

本地 `README.md` 第 57～65 行给出的表述是“建议”，并明确说明背后安装不是额外计分或验收条件。因此：

- 当前机器人还没有篮子。
- 可以先实现逐件抓取、逐件送桶。
- 如采用随车收集方案，需要自行提交具有真实物理效果的篮子模型。
- 放进随车篮子不得分，最终仍要把物体送进固定橙色桶。

随车篮子可以理解成临时货厢；场地里的橙色桶是最终交付位置。篮子减少往返次数，同时增加装篮、运输保持和卸载的难度。

## 7. 篮子怎样进入这个工程

### 概念结构

`base（机身）— fixed joint（固定连接，像焊在一起）— basket link（篮子这个零件）`

URDF 是机器人的结构说明文件。新增一个篮子零件，再用固定连接装到 `base`，可以让它随着机械狗移动，并保持原有 19 个可控关节。相机和雷达仍保留原父 link。

安装位置是相对机身描述的：机身坐标 x 朝前，后方对应负 x；这不是要求篮子始终朝世界坐标某个固定方向。

### 一个真正能装东西的篮子至少包含

| 内容 | 大白话解释 | 设计作用 |
| --- | --- | --- |
| 底板、侧壁与上部开口 | 有底有墙、上面能放入 | 支撑物体并减少掉出 |
| Visual，外观 | 屏幕上看见的形状 | 便于观察 |
| Collision，碰撞体 | 仿真真正用于计算接触的实体形状 | 让物体不会穿过底板和侧壁 |
| Mass，质量 | 篮子有多重 | 影响载重和稳定性 |
| Inertia，转动惯量 | 篮子转起来有多费劲，与质量分布有关 | 影响物理模拟和身体响应 |
| 固定连接与安装位姿 | 装在哪、朝哪、怎样随身体运动 | 保证模型结构正确 |

适合第一版的概念是低矮、上部敞开的简单筐；底板和各面侧壁可以分别使用薄长方体，不必先制作复杂 CAD 网格。CAD 是画精确三维机械零件的工具。尺寸和安装位置当前尚未计算，不能当成已完成设计。

仅把整个空心筐用一个实心碰撞形状包住，可能使筐内也被仿真当成实体。采用分别描述的底板和侧壁更容易核对内部是否真正空着。

### 尺寸应由任务反推

1. 机械臂能否在篮口上方停住并松爪？这叫可达性，即手够不够得到。
2. 运输和收臂时，手臂会不会撞篮沿？从地面到篮口的全过程都要检查。
3. 篮子会不会挡住后腿、机身或传感器？不能只检查静止站立时的外观。
4. 想先装几件？本包每件 0.5 kg，应从轻载、小批次概念开始，不能把容量大等同于可稳定运输。
5. 放进去以后能否再取出来？上口、深度、堆叠情况和腕部视线共同决定卸载难度。

## 8. 卸载方式应与篮子同时设计

| 方案 | 怎么卸货 | 当前判断 |
| --- | --- | --- |
| 固定浅篮＋机械臂逐件取出 | 到橙色桶边，再从随车篮子中抓起物体投放 | 最贴合保持现有可控关节的初版概念，但增加二次抓取，需避免堆叠过深 |
| 机械臂操作的被动翻转/开门机构 | 手臂拉动把手，使内筐或门板活动 | BinWalker 的实物思路；需额外机构建模、碰撞与质量参数，并核对本包资产检查兼容性 |
| 加电机主动倾倒 | 新增控制翻斗的电机 | 会改变控制结构，不作为当前保持 19 个可控关节方案的起点 |

固定安装的篮子不会自行翻转。需要倾倒时，必须有真实可动机构和由物理接触驱动的过程；不能以物体位置写入代替卸载。

BinWalker 的实体容器利用 Z1 提起把手，带动内部筐和门联动，是值得观察的机械思路。我们现在先理解其原理，不承诺其尺寸、被动关节、网格或操作动作适合本教学包。

## 9. 接下来的学习安排

建议围绕一个问题学一小组概念，然后立即对应到源码，不一次堆叠大量术语。

1. **从图片到抓取目标。** 看懂分割、深度、坐标系、抓取点和抓取方向；画出一个芥末瓶从图像到 `base` 的信息流。
2. **从抓取目标到关节动作。** 看懂正运动学、逆运动学、预抓取点、轨迹、状态机；对照 BinWalker 的几个动作函数和本地 `select_arm_target()`。
3. **从单件抓取到暂存运输。** 看懂固定连接、碰撞体、质量、重心、篮口可达和二次抓取；先画装入与取出的两条路径。
4. **从局部动作到完整任务。** 补上自主搜索、导航、持物验证、投放确认和失败恢复。

第一版可以先用手持物体送桶完成闭环，再将“装篮与卸篮”插入流程。当前只研究以上信息流和设计，不进入实操训练阶段。
