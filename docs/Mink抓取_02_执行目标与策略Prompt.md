你是负责交付代码和实验结果的服务器端工程师。结合《Mink抓取_01_环境配置Prompt.md》直接执行：读取工程，新增独立测试代码，适配现成 Mink 求解器，在服务器运行、定位问题并修复，最后交付可复现命令、录像和逐次结果。不要只返回架构、伪代码、安装成功或未经物理验证的 IK 结果。

## 1. 本轮唯一目标

**让工程提供的 B2＋Z1 在地面真实站立，面前固定放一个工程自带物体，用 Mink 求解 Z1 动作，通过实际夹爪接触把物体抓离地面并保持。**

本轮无篮子、不放背部、不导航、不做物体识别、不接语言模型、不训练 RL、不完成 18 物体收集。采用固定已知抓取目标，以排除感知和搜索干扰；交付标题必须注明“已知目标位姿的抓取诊断”。

环境为 Isaac Sim 5.1＋Isaac Lab 2.3.2 workstation＋ROS2 Jazzy，Python 3.11。先读取第 1 份指令的环境报告，必要检查通过后继续。物理仿真使用 Isaac，Mink＋MuJoCo 只做运动学求解。优先候选 Mink 1.0.0＋MuJoCo 3.3.7，最终以服务器验收后的锁定版本为准。

## 4. 初始布局与已知目标的边界

机器人朝前，物体摆在其正前方地面。可保留机器人原起点 (-10,-10,0.6)，以机器人前方 +x 方向定义物体位置。物体距离不要随意写死：可以从 0.55、0.65、0.75 米做有限候选，筛除与脚/身体碰撞、IK 不可达或轨迹穿身的布局，再锁定一个布局用于验收。

从项目自带三种物体中选择夹爪开口能覆盖的一种，优先检查芥末瓶可夹部位；若不匹配，可以选糖盒窄边或香蕉的可夹局部，记录选择理由。保持原资产尺寸、质量 0.5kg、重力和碰撞，用工程既有的物体动力学配置。物体姿态固定且稳定；沿用或调整了哪种初始朝向都应在配置中写清。这是机械诊断，不声称已经覆盖正式布局与全部类别。

初始化时可配置物体位姿，按实际包围盒计算落地高度，避免嵌地或悬空；先等待机器人和物体稳定，再开始动作。稳定后因沉降产生的小偏差要记录，不能在抓取中通过反复重置物体掩盖。

控制器使用测试配置中明示的固定抓取点和朝向，以及机器人自身状态。场景对象的实时真实位姿只供 evaluator 计算抬升、离地和掉落指标，不反馈给抓取控制器；不得把它包装成视觉感知。录像相机本轮只用于观察，不要求检测网络。

## 5. 复用现成 Mink，不从头开发 IK

参考仓库：https://github.com/iit-DLSLab/trash-collection-isaaclab

固定提交：76c51c4c08e5762d00c75f36cb07aa3e525d6990。

重点获取 deploy/ik_mink.py、deploy/state_machine.py、deploy/mujoco/models/z1/ 中必要模型及各自许可证。只引入必要文件，不安装其整套 Aliengo 训练/ROS 环境，不下载用不上的操作权重。复制代码时保留声明并记录来源。

适配要求：

1. **以本地 URDF 对齐几何。** 原求解模型为 z1_floating.xml，挂载位置 (0.22,0,0.055)、首臂节有约 90 度固定旋转，状态机又包含首关节 1.57 的编码器偏移。本地挂载为 (0.2,0,0.09)，首关节无该固定旋转。必须统一坐标与零位，不能照抄偏移。
2. **使用固定机身的臂求解模型。** 可将求解用模型约化为六个臂关节，或者用现成 DofFreezingTask 冻结虚拟 basepitch/basez；不输出当前 B2 策略无法执行的高度/俯仰指令。这里“固定”只指 IK 模型，不是把 Isaac 中的狗锁死。
3. **对齐 TCP。** TCP 指两指实际夹持中心。BinWalker 的 attachment_site 在 link06 沿 x 方向 0.15m，必须结合本地夹爪几何核对，不能直接把 link06 原点当作夹持中心。
4. **统一旋转表示。** Isaac/MuJoCo/Mink 相关四元数按实际 API 检查 wxyz/xyzw；SciPy 的默认输出通常是 xyzw。显式转换并用简单姿态核对，不靠目测猜顺序。
5. **同步实际状态。** 每次求解从实际臂关节角和机器人姿态出发，将目标变换到正确臂基坐标系。不得把上一帧的理想关节角当成机器人已到位。
6. **核对限制。** 使用本项目实际可执行的关节范围；若配置的软限位更保守，按有效范围求解。保持合理速度，初次接近可把臂的目标速度设为约 0.3–0.5rad/s，最终由实际误差和接触效果调整并记录。
7. **修正成功条件。** 原封装允许 10cm 位置误差、只用位置判成功，碰撞约束未启用。不能照搬。先用位置误差 <=5mm、朝向误差 <=5°作为空载到位目标，同时检查实际执行误差；这些是本轮拟定标准，不是现成实测性能。
8. **使用有限迭代与热启动。** 在选定的 Mink API 上复用 FrameTask、PostureTask、ConfigurationLimit 和现成 solve_ik；若 QP 无解或达到迭代上限，明确返回失败。不要只改“成功阈值”把失败变成功。
9. **检查路径。** 本工程默认关闭机器人内部自碰撞，不能把穿过机身/腿的轨迹判定为成功。至少对预抓取、接近和抬升的采样轨迹做保守几何避让检查；需要碰撞约束时启用现成工具，不从头开发通用规划器。

先通过本地 URDF 与求解模型的正运动学对照，再做 IK 往返检查。检查多个非零姿态和预抓取/抬升目标，避免两个函数共用同一错误坐标也互相“验证通过”。这些计算在服务器完成。

## 6. 执行策略：按仿真步推进

实现以下状态，每个状态有到位条件、最长持续时间和失败原因：

```text
SETTLE        等待真实站稳和物体落稳
OPEN          充分张开夹爪
PREGRASP      到物体附近的预抓取点
APPROACH      缓慢接近，保持夹爪朝向
CLOSE         限速闭爪，等待接触建立
LIFT          用 Mink 求出抬升动作并缓慢执行
HOLD          保持抓取至少 3 秒仿真时间
DONE / FAIL   保存结果并结束本次试验
```

Mink 至少实际参与预抓取、接近和抬升目标求解，不能运行一次 import 就用完全手写轨迹冒充 Mink 抓取。

初始只探索少量可解释候选，例如抓取高度、夹爪朝向、预抓取距离与接近速度；优先检查开口是否覆盖目标截面、TCP 是否进入两指之间。不能简单把物体中心等同于可夹部位，也不能让夹爪扎入地面。

OPEN/CLOSE 必须考虑夹爪 0.25rad/s 的实际限速，可设置约 8–10 秒的有限阶段超时，结合实际角度和速度判断是否完成。夹住物体后夹爪可能到不了 0，不能因此直接判失败；反过来，夹爪到了 0 也不证明抓到物体。

按 CONTROL_DT 累积仿真时间，每次控制更新后实际推进 Isaac；禁止直接复制 BinWalker 的 time.sleep 等待循环。Mink 内部可做有限数值迭代，但外层动作必须持续推进物理。检查姿态偏斜、底盘漂移、动作 NaN、限位和异常接触，超限及时结束并记录。

抬升时维持夹爪预紧目标，不执行完整 controller.reset()，不立即松爪。物体掉落或狗失稳后，保留日志和视频，再正常重置进入下一次试验。

## 7. 严格验收

本轮的验收阈值先写入配置，调试后锁定，不能看完最终结果再改阈值。

一次抓取成功需要同时满足：

- 物体根点/质心相对其稳定起始高度上升至少 0.10m；
- 物体包围盒最低点离地至少 0.02m，排除仅旋转造成根点升高；
- 上述离地状态持续至少 3 秒仿真时间，物体位于两指夹持区域并随夹爪运动；不能只是被顶起、托在机身上或瞬间弹起；
- 保持阶段夹爪仍在夹持，机器人未跌倒或发生机身/髋/大腿异常触地；可先设机身倾斜不超过 15°、水平漂移不超过 0.10m，作为本轮保守试验阈值；
- 没有将物体附着到夹爪、创建隐藏固定约束、禁用重力、冻结机身、缩小物体、减轻质量或在动作中瞬移物体。

允许 evaluator 读取物体真实位姿和包围盒来测量这些指标，其数据流必须与 controller 分开。必要时结合两指接触信息与录像排除“托住而非夹住”；接触计数或夹爪角度不能单独作为成功证明。

调试获得一次成功后，冻结全部配置，做 5 次独立 reset 的完整重复试验。逐次报告，不删除失败样本。目标为至少 4/5 成功；若只有一次成功，应报告“已有单次成功，重复性未达标”，不能称稳定完成。

## 9. 遇到失败如何处理

按“模型对齐 → 可达性 → 实际到位 → 开口/接近 → 接触 → 抬升 → 站立稳定”顺序定位，修复后只重跑受影响环节，再做最终验收。遇到一次失败不要直接换大模型、重训 RL 或照搬 Aliengo 权重。

如果固定机身条件下地面目标不可达，先在不碰脚的有限前方布局和合理夹爪朝向中检查。若始终不可达，报告可达范围和失败目标；本轮不要擅自新增身体俯仰控制、把物体放上台子或修改机器人来宣布成功。

如果物体进入两指之间但抓不住，优先检查 TCP、夹持部位、实际闭爪等待、接触几何与保持目标。保持原质量、夹爪力矩/速度上限和原始摩擦设置；必要的接触求解迭代数等数值修复可以在独立场景中小幅调整，但必须给出前后配置和理由，不能使用异常摩擦或附着机制。

预算优先用于得到一个能解释、能复现的真实抓取结果。若经过有限、有依据的修复仍无法通过，交付失败证据与最小修复建议，明确标记任务未完成；不能用“IK 求解成功”“程序退出码为 0”或“已生成代码”替代物理抓取验收。
